ProSE desktop (left) next to the web app (right)

These screenshots are of desktop 0.1.0, whose bundled example was the web app's (the simulated DatabaseSuitability run): the pairs show the same data. From 0.1.1 the desktop's example is OpenMS' E. coli run (Ecoli_MS2_small.mzML, LTQ Orbitrap XL, CID, against the E. coli K-12 proteins, fragments at 0.5 Da), the top bar has the OpenMS logo, the settings card has both "Advanced" and the web app's "All 72 parameters" dialog, and many grey texts are reworded. A new run of e2e/screens.shot.ts shows the E. coli example, which the web screenshots do not have.

Both at 1440×900. Desktop: the debug build in WebKitGTK under Xvfb (e2e/screens.shot.ts), the pinned ProSE tool, the bundled example with PeptDeep on. Web: the C12 build in headless Chromium (/scratch/sachsenb/prose-app-screenshots/, copied to web/). Intended differences: no engine chip in the top bar, no memory estimate, file paths instead of uploads, "Advanced" instead of "All 72 parameters". The other differences are listed under each pair.

Fonts: monospace fonts are bundled, so that WebKitGTK does not fall back to the wider system DejaVu Sans Mono (src/assets/fonts/README.txt, all SIL OFL). font-mono (accessions, file names) is Liberation Mono, the font the web screenshots rendered it with. Peptide sequences (the PSM list, the protein panel's peptides, the fragment ladder, the ion table, the coverage map) are Inconsolata: 0.5 em wide like the font headless Chromium fell back to for them on this node (WenQuanYi Zen Hei Mono, not bundled: GPL), so sequences take about the same width, but the glyph shapes differ slightly from the reference (Inconsolata's letters look a little smaller and lighter). WebKitGTK sets the 12.5 px text at 13 px with whole-pixel advances: Liberation Mono runs 8 px per character (7.5 px in the web app), Inconsolata 6 px (6.25 px), so a cut-off sequence shows one character more than in the web app (PSM view: "IEEPSVVETTHQDSPLP…" here, "IEEPSVVETTHQDSPL…" there).
